# multivoice-reader

把小说读给你听：分出旁白和每个角色，给他们配上不同的声音，按台词的情绪来读。
拆分、选角、合成语音全部在你自己的电脑上完成，不调用任何云端接口。

目前只支持 Apple Silicon 的 Mac（模型通过 MLX 运行）。项目还在早期，接口和文件格式都可能变。

## 听一下

下面两段是同一份脚本（[`docs/samples/night-rain.json`](docs/samples/night-rain.json)，原创的一小段，三个角色）用 `mvr generate` 读出来的，没有做任何后期。点开后可以播放或下载。

| 音频 | 旁白 | 周远 | 林晚 | 奶奶 |
|---|---|---|---|---|
| [night-rain.mp3](docs/samples/night-rain.mp3)（自动配的声音） | 激昂男旁白 | 冷峻男主 | 干练女强人 | 慈祥老妇 |
| [night-rain-other-voices.mp3](docs/samples/night-rain-other-voices.mp3)（指定了声音） | 温柔女旁白 | 少年主角 | 温婉淑女 | 慈祥老妇 |

脚本里周远有一句标了愤怒，林晚有一句悲伤，奶奶有惊讶和高兴各一句，其余是中性。
内置的 25 个声音各自的参考录音在 `src/multivoice_reader/voices/<声音>/ref.wav`，也可以直接听。

## 运行条件

- **机器**：Apple Silicon 的 Mac。只在 M3 / 16 GB 内存 / macOS 27 上开发和测试过。
- **内存**：建议 16 GB。各个模型运行时的内存峰值见「用到的模型」，同一时间只跑一个。8 GB 的机器没有测过：
  按峰值算，用 Qwen3-1.7B 拆分（2.2 GB）应该可以，合成语音（4.0 GB）会比较紧。
- **硬盘**：模型在第一次用到时下载。默认的拆分模型加语音模型共 5.7 GB；声音复刻另外要 1.4 GB。
- **软件**：[uv](https://docs.astral.sh/uv/)（它会装好 Python 3.11 和依赖）和 ffmpeg（`brew install ffmpeg`）。
- **网络**：只在下载模型时需要。之后拆分、合成、复刻都不联网。

Windows 和 Linux 上现在跑不了朗读和网页。`finetune/` 下训练和打分的脚本可以在 NVIDIA 显卡上跑。

## 两件互不相干的事

```
小说.txt ──拆分──> 朗读脚本.json ──朗读──> 声音
```

- **拆分**：把小说切成章，判断每句话是谁说的、带什么情绪，写成一份朗读脚本。它不管声音。
- **朗读**：把一份朗读脚本读出来，给每个角色配一个声音。它不管脚本是怎么来的：拆分出来的、手写的、别的工具生成的都能读。

两边只靠朗读脚本这一个文件衔接，各自有一个命令和一个页面。

## 用起来

```bash
git clone https://github.com/qiaob/multivoice-reader.git
cd multivoice-reader
```

命令行：

```bash
uv run mvr split 小说.txt -o 脚本.json          # 拆分；--chapters 1-20 只拆这些章
uv run mvr generate 脚本.json -o 输出目录       # 朗读成音频，每章一个 mp3
uv run mvr voices                               # 有哪些声音可以用
```

`split` 可以用 `--model` 换一个判断说话人和情绪的模型：`qwen3.5-4b`（默认，最准）或 `qwen3-1.7b`（最快最省内存）。它们的差别见「用到的模型」。

`generate` 可以指定声音：`--narrator 声音名` 是旁白，`--cast 张三=声音名` 是某个角色，可以给多次；没指定的角色按性别和年龄自动配。

两个命令都不依赖别处的存储。`split` 每拆完一章就把脚本写一次，中途停了，用同样的命令再跑会接着拆。`generate` 写的所有东西都在输出目录里：章节音频在最外层，`work/` 下是脚本、谁用哪个声音、每一句的音频；再跑一次会接着做。

网页：

```bash
uv run mvr web
```

顶部四个页签：

- **拆分**：首页是小说列表，可以一次加很多本 txt。每本填好拆到第几章，点「拆分」就排进队里，按先后一本一本拆。右上角可以选拆分用的模型，点「拆分」时选着哪个，这本书就用哪个。点书名进去能看到每章拆出来的结果和拆出来的角色。拆好的部分可以导出成脚本，或者送去朗读。
- **朗读**：首页是脚本列表（拆分送来的，或者自己添加的文件，可以一次加很多份）。点一份进去听：左边是章节，中间是正文，右边是每个角色用的声音，可以改。正文里已经合成好的句子是深色的，点任何一句可以从那里读起。也可以让一份脚本「整份提前合成」，没人在听的时候它在后台慢慢合成。
- **声音试听**：声音库里的每个声音都可以听；自己的声音可以导出成 `.voice.zip` 或删除，也可以添加别人导出的声音包。
- **声音复刻**：从文件、麦克风或系统正在播放的声音复刻一个新声音。

合成速度和播放速度差不多，所以朗读页是边合成边读：读到还没合成的句子会停下来等。它总是优先合成你正在听的位置，并提前准备后面两章。

拆分、合成、复刻的模型一起放不进内存，所以后台同一时间只做一件事，按这个顺序挑：复刻声音；给正在听的那份脚本合成；拆排着队的小说；整份提前合成。前面的事来了，后面的会停下让路，之后自动接着做。

## 朗读脚本

一个 JSON 文件，格式定义在 `src/multivoice_reader/script.py`：

```json
{
  "format": "multivoice-reader.script",
  "version": 1,
  "title": "书名",
  "characters": {
    "张三": {"gender": "男", "age": "青年"}
  },
  "chapters": [
    {
      "title": "第一章 夜雨",
      "lines": [
        {"text": "夜色渐深，老街尽头的路灯忽明忽暗。"},
        {"speaker": "张三", "emotion": "愤怒", "text": "你到底还要骗我多久？"}
      ]
    }
  ]
}
```

- 一句话只有 `text` 是必须的。不写 `speaker` 就是旁白，不写 `emotion` 就是中性。
- `emotion` 是这七种之一：中性、高兴、悲伤、愤怒、恐惧、厌恶、惊讶。
- `characters` 可以不写。`gender` 是男、女，`age` 是儿童、少年、青年、中年、老年；写了就按它自动配声音，没写的角色先用旁白的声音，到朗读时再改。
- 几句话要显示成同一段，就给它们相同的 `para`（一个数）；不写则每句一段。
- 脚本里没有任何和声音有关的内容。同一份脚本可以配不同的声音读多遍。

## 拆分是怎么做的

1. **切章切句**：按「第 X 章」切章，按引号把正文分成旁白和对白。纯规则。
2. **判断**：一个本地语言模型判断每句对白是谁说的、带什么情绪，并记下新角色的性别和年龄段。它只打标签，不改写原文。

语言模型会判断错。说话人标错时，那句话会用错声音，但文字不会错。

这两个模型都是在这件事上微调过的（真实小说的片段加合成数据），权重在 `src/multivoice_reader/models/`。
微调过的模型只学了「谁说的、什么情绪」，所以判断新角色的性别和年龄时，用的是同一个模型关掉微调权重后的样子；
Qwen3-1.7B 在这一步上比较弱，偶尔会把年龄判断错。
训练数据、训练脚本、原始权重和全部成绩在 `finetune/` 下，见 `finetune/RESULTS.md`。

## 声音

一个声音就是「一段参考录音加上录音里说的话」；用它说话，就是让语音模型照着这段录音的音色来读，并带上情绪。声音库有两个来源：

- **内置的声音**：`src/multivoice_reader/voices/` 里的原创音色，按文字描述生成，不是任何真人的声音。自动配声音时从这里面选。
- **你自己的声音**：从一段 3 到 20 秒的录音复刻出来，存在 `~/.multivoice-reader/voices/`。它们不会自动分给角色，要自己选。

复刻前会先把人声从背景音里分出来；复刻完用朗读时的模型试读几句，听到的就是朗读时的效果。
只复刻你自己的声音，或已获得本人同意的声音。

`audition/` 目录下是当初生成内置音色用的脚本，平时用不到。

## 用到的模型

全部在本机运行，第一次用到时从 Hugging Face 下载。内存峰值和速度是在 M3 / 16 GB 上测的。

判断说话人和情绪（二选一，一次回答里两样一起判断）：

| `--model` | 模型 | 下载 | 内存峰值 | 拆分速度 | 说话人 / 情绪 |
|---|---|---|---|---|---|
| `qwen3.5-4b`（默认） | Qwen3.5-4B 4bit，加微调权重 | 2.9 GB | 4.2 GB | 每秒约 64 字 | 97% / 98% |
| `qwen3-1.7b` | Qwen3-1.7B 4bit，加微调权重 | 0.9 GB | 2.2 GB | 每秒约 130 字 | 90% / 96% |

- 拆分速度是按正式流程拆一本网络小说的前两章（5700 字，72 句对白）量的，不算加载模型的几秒钟。
  一章 3000 字，两个模型分别要 50 秒和 25 秒左右。
- 两个都是微调过的。作为对照，没有微调的 Qwen3.5-9B（下载 5.6 GB，内存峰值 6.6 GB）每秒约 38 字，同一份测试集上是 91% / 84%。
- 准确率是在这台 Mac 上对一份手工标注的小测试集（13 本书，186 句对白）打的分，句数少，3 个百分点以内的差别不算数。
  在没参加过训练的另外 10 本书（783 句）上，两个微调模型在显卡上未量化时是 95% / 96% 和 91% / 93%，
  详见 `finetune/RESULTS.md`。

其他：

| 用途 | 模型 | 下载 | 内存峰值 |
|---|---|---|---|
| 合成语音（照着参考录音的音色读，并带上情绪） | Ming-3.0-tts-0.5B | 2.8 GB | 4.0 GB |
| 复刻时分离人声 | Mel-Band-RoFormer | 0.4 GB | 没有测 |
| 复刻时识别录音里说的话 | Qwen3-ASR-0.6B 8bit | 1.0 GB | 没有测 |
| 复刻时去噪 | DeepFilterNet | 很小 | 没有测 |
| 设计内置音色（已经做好放在仓库里，平时用不到） | Qwen3-TTS VoiceDesign | | |

合成语音的速度和播放速度差不多：上面那段 45 秒的示例，连加载模型一共用了 40 秒。

在 NVIDIA 显卡上（RTX 5070 Ti 16 GB，Windows，PyTorch，未量化，一次 8 段）只能跑标注这一步，是训练和打分时用的：
同一份 186 句的测试集，Qwen3.5-4B 每秒标 8.8 句，Qwen3-1.7B 每秒 15 句；这台 Mac 上分别是每秒约 1 句和 2 句。

## 开发

```bash
docker run --rm -v "$PWD":/work -w /work python:3.11-slim \
  sh -c "pip install -q ruff pytest numpy && ruff check src tests && PYTHONPATH=src python -m pytest -q tests"
```

测试只覆盖不需要模型的部分：切章切句、数字读法、脚本格式、选角、拆分和朗读两边的存取、声音库。

目录：

| 目录 | 内容 |
|---|---|
| `src/multivoice_reader/` | 程序本身。`web/` 是网页，`voices/` 是内置的声音，`models/` 是微调好的标注模型（MLX 格式） |
| `tests/` | 测试 |
| `docs/samples/` | 示例脚本和它读出来的音频 |
| `finetune/` | 标注模型是怎么训出来的：脚本、数据（`data/`）、标注说明（`labelling/`）、原始权重（`adapters/`）、成绩（`RESULTS.md`） |
| `audition/` | 当初生成内置音色用的脚本，平时用不到 |
